Inside layernorm

SAM 3's transformers use LayerNorm: subtract the row's mean, divide by its standard deviation, then scale and shift each channel. The language models in this atlas use RMSNorm instead (rmsnorm), which skips the mean and the shift. This kernel normalizes 1024-wide rows in the ViT and text encoder and 256-wide rows everywhere after them, 276 launches for an image and two prompts. It also writes the result in the form the next kernel reads: f16 for a matrix product, f16 with the position embedding already added for the attention layers whose queries and keys get it, or f32 back into the stream for the decoder's post-norm layers.

y[i] = (x[i] − μ) / √(σ² + ε) · w[i] + b[i],  μ = mean(x), σ² = mean((x − μ)²), ε = 10⁻⁵   // outputs: y32 (f32), y16 = f16(y), yp16 = f16(y + pos)

A warp per row: sum, then squared deviations, then the output

Lane l reads 4 floats at columns 4l, 4l + 128, 4l + 256, …: the whole warp covers 512 contiguous bytes per access. Each pass re-reads the row from global memory; after the first pass it comes from L1. The two reductions are warp butterflies, with no shared memory and no barrier. Pick the row width and a lane.

Why it is built this way

    

      

        
Two passes for the variance

        
The variance could come from one pass as E[x²] − E[x]², but that subtracts two large, nearly equal numbers whenever a row's mean is large next to its spread. SAM 3's residual streams are not centred, and the ViT's has channels near 200. Raise the row offset above: for a row with a spread of 2.5, the f32 one-pass variance is off by about 0.05% at +100, 0.7% at +200 and 2% at +300, while the two-pass result stays exact. The kernel first computes the mean, then sums (x − μ)². The extra pass re-reads 4 KB from L1. The reference is PyTorch's nn.LayerNorm, which is two-pass as well; in the per-stage comparison the normalized stream matches it to 1.5 · 10−3 relative, most of which is f16 rounding of the inputs before it.

        
A warp, not a block

        
A row of 256 or 1024 floats is 8 or 32 values per lane, which is too little work to spread over a block of 1024 threads. That is what rmsnorm does for the LLMs' 4096-wide rows of one token. Here there are thousands of rows (5184 image tokens), so a warp per row keeps every SM full, and each reduction is 5 butterfly steps with no bar.sync.

      

      

        
The outputs are what comes next

        
Before a matrix product the next kernel wants f16 (y16), so no separate conversion runs. Before the attention layers whose queries and keys carry a position embedding (the fusion encoder's self-attention, the decoder's three), it wants f16(y + pos) as well: yp16 adds the f32 position row and converts, while y16 gives the plain value input. The decoder's layers are post-norm (Add & Norm after each sub-layer), so there the result also replaces the stream itself (y32 = x, in place: each lane reads its 4 values before it writes them). Any of the three can be 0 and is then skipped.

        
LayerNorm in SAM 3

        
Every norm in SAM 3 is a LayerNorm with weight and bias, ε = 10⁻⁵, from ln_pre after the patch embedding to the decoder's presence_token_out_norm. The only other norm is the pixel decoder's GroupNorm (gn_stats), which normalizes over all pixels of 32 channels instead of over one token's channels.
