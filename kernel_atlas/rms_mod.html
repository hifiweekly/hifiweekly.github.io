MiniMax-H3 · minimaxh3.ptx · one warp per row, the row's segment picks its modulation

Inside rms_mod

MiniMax-H3's diffusion transformer runs text, audio and video tokens through the same 50 blocks as one sequence, but each kind of token gets its own AdaLN modulation: a shift and a scale for the norm in front of attention, another pair in front of the feed-forward, both computed from the timestep. This kernel does the RMS norm and the modulation in one pass over each row, and reads which modulation to use from a one-byte segment id per token, so the 541 rows of a 256 × 256 video (19 text, 74 audio, 448 video) are one launch instead of three. It is also the plain RMSNorm of the other three networks: leave out the modulation, the weight or the segments and the same code normalizes the text encoder's and the video decoder's rows.

v = x / √(mean(x²) + ε) · w,   y = v + v · scale[s] + shift[s],  s = seg[row]   // outputs: y16 = f16(y · oscale), y32 = y; w, shift/scale, seg each optional

A warp per row, and a segment byte per row

The strip is the diffusion transformer's sequence for a 256 × 256, 22-frame video: the refined prompt, the left and right audio channels, then 7 × 8 × 8 video patches. Each token's segment is timestep row × 3 + modality: video and text use the video timestep, audio its own (the audio schedule runs on a different sigma). Click a token to normalize its row. The modulation values are the model's own: block 0's shift and scale vectors, computed from its AdaLN weights at the first step (t = 0) or near the end (t = 0.99).

Why it is built this way

    

      

        
A byte per row instead of a launch per modality

        
The reference implementation (stable-diffusion.cpp) slices the sequence into its text, audio and video spans and normalizes and modulates each slice separately, then concatenates the results for the shared q, k, v product. Here the slices never exist: the sequence stays one [541][5376] matrix, a u8 array says which (timestep, modality) row of the modulation table each token uses, and the shift and scale pointers plus a stride turn that byte into an address. The same byte feeds the gated residual add in gemm_f16's epilogue, so a block of the transformer is four norms-and-products over the whole sequence, never per modality.

        
What the model does with it

        
Block 0's scale vectors are near −0.9 for video tokens: (1 + scale) multiplies the normalized row by about 0.1, so the video tokens enter the first attention mostly through the shift, a learned per-channel offset. The gates, applied after attention and after the feed-forward, grow with depth (the adaln page plots them), and in block 49 the text tokens' gates and their feed-forward modulation are exactly zero: the final layer only reads audio and video rows, so a text update in the last block would be thrown away, and this pruned checkpoint has none.

      

      

        
One norm for four networks

        
Every pointer is optional. The text encoder (Qwen3-VL) calls it with a weight and no modulation, ε = 10⁻⁶; the video VAE with a weight; the token refiner and the final layer write the f32 result (y32) back into the stream instead of an f16 copy; inside the 50 blocks it writes only the f16 operand of the next GEMM. Predicates set once per row skip what is absent, so the plain norm costs the same loop as the modulated one minus two loads.

        
A warp, not a block

        
The rows are 2048 to 5376 floats: 16 to 42 vector loads per lane. With 541 rows (or 1797 in the video decoder) there are enough warps to fill the 56 SMs, so each row is one warp and the reduction is five butterfly rounds with no shared memory and no barrier. The second pass re-reads the row from L1 rather than holding 168 floats per lane in registers.

        
The f16 output is scaled

        
oscale multiplies the f16 copy only. The engine passes 1 everywhere today; it exists so an operand that would overflow f16's 65,504 can be scaled down and the GEMM's alpha can undo it, the same trick the feed-forward uses between fc1, swiglu and fc2.
