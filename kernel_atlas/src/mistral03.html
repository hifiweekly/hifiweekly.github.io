mistral03.ptx - hand-written PTX kernels for Mistral 7B v0.3 (dense, text) inference, made for Mistral-7B-Instruct-v0.3. They are the Llama 3.1 engine's kernels unchanged (../llama31): the model is the same shape. The host (mistral03.c) runs a layer as (T tokens at a time; sizes for the 7B: 32 q heads, 8 kv heads, 128 dims): xn = rmsnorm(x) * attn_norm rmsnorm, quant_q8 q, k, v = Wqkv . xn (4096 | 1024 | 1024) mv_q / gemm_q q, k = RoPE (adjacent pairs, base 1e6) rope_kv (k, v also to the f16 KV cache) y = Wo . softmax(q K^T / sqrt(128)) V attention, quant_q8, mv/gemm x += y (the matrix kernels' resid) xn = rmsnorm(x) * ffn_norm g|u = [Wgate; Wup] . xn, h = silu(g) * u mv/gemm, swiglu x += Wdown . h mv/gemm and finally logits = Wout . rmsnorm(x) * output_norm, next = argmax. Weights are ggml's quantized blocks (see quant.h); a matrix is a q array and (for some types) an s array, each [rows][a fixed number of bytes per row], laid out so that every load is aligned: Q8_0: q int8 [cols], s = d f16 [cols/32] Q4_1: q = qs [cols/32][16], s = dm f16x2 [cols/32] IQ4_NL: q = qs [cols/32][16], s = d f16 [cols/32] Q4_K, Q5_K, IQ4_XS: the 144 / 176 / 136-byte blocks as stored [cols/256] Q6_K: q = ql | qh | scales (208 bytes) [cols/256], s = d f16 [cols/256] Q3_K: the 110-byte blocks padded to 112 [cols/256] IQ3_S: 112-byte blocks [cols/256], fields reordered: qs[64] signs[32] qh[8] scales[4] d, 2 bytes padding The 8B Q8_0 file needs only Q8_0; the other formats let the engine run other quantizations of the model (Q4_K_M, IQ4_XS, ...). Activations entering a matrix are quantized to int8 in blocks of 32 (as llama.cpp does): xq int8 [n] and xds f32x2 [n/32] = {d, d * sum_j q_j}. A weight block with half scales s_0, s_1 and offset m (w = s_h q + m) then contributes d_x (s_0 dot(q_w, q_x)_0 + s_1 dot(q_w, q_x)_1) + m d_x sum(q_x) with exact integer dot products (dp4a in the matrix-vector kernel, int8 tensor-core mma in the GEMM).

Weight decoding. unpack16 turns 16 weights of a row into int8 with a scale (and, per 32 values, an offset), whatever the row's ggml type; the matrix-vector kernel and the GEMM both go through it, so they read every format the same way.
