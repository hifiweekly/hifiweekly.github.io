Kernel Atlas

Interactive walkthroughs of the GPU kernels behind the three inference engines in this project: two text generators and one text-embedding encoder. Each page steps through one kernel the way the hardware runs it: which thread touches which bytes, where threads cooperate, and the matching lines of the hand-written PTX and of an equivalent CUDA C++ version. Every number on the pages is computed in your browser by re-running the kernel's float32 arithmetic on generated data.

How to read a page

Step through itPlay, the arrow buttons, the slider, or your keyboard's ← and → keys move one step of the kernel at a time.
Point at the dataHovering over a cell names the element, the thread that owns it and the values involved. Clicking selects that thread so every panel follows it.
Read the codeThe source panel highlights the lines for the current step, in hand-written PTX or the equivalent CUDA C++.
Ask whyEach page ends with the design reasons: the access pattern, the reduction scheme, what the kernel avoids.

Names used on every page

KernelsThe PTX .entry name, e.g. swiglu_oai; its page is swiglu_oai.html.
Enginesgpt-oss, Gemma 3, EmbeddingGemma 2, or gpt-oss + Gemma 3 when the PTX is identical in both files. emb2.ptx copies rmsnorm, add_rmsnorm, geglu and gemm_q8 from gemma3.ptx unchanged; their pages list it under "runs in".
TensorsGGUF names without blk.N.; shapes are rows × cols (output × input); types F32, F16, BF16, Q8_0, Q5_0, MXFP4.
Layers and bufferslocal = sliding-window layer, global = full context. Buffers use the engine's names: x, xn, qkv, att, y, gu, h, logits.

Routing and sampling

mv_f32gpt-oss

The MoE router: 32 expert scores per token from a float32 32 × 2880 matrix.

Shows: one warp per row, 90 coalesced loads per lane, the logits handed to router_topk.
grid (4, tokens) · 256 threads
router_topkgpt-oss

Picks each token's 4 experts from 32 logits and softmaxes their weights.

Shows: four rounds of warp argmax with tie-breaking, a softmax over the picks.
grid (tokens) · 32 threads
moe_sortgpt-oss

Groups (token, expert) pairs by expert so each expert's weights are read once per chunk.

Shows: histogram, serial scan, scatter with atomics; arbitrary but harmless order.
1 block · 1024 threads
moe_combinegpt-oss

Mixes the 4 expert outputs with the router weights and adds them to the residual stream.

Shows: the [token][slot][2880] layout, one element's four FMAs, grid-stride over tokens.
≤ 448 blocks · 256 threads · grid-stride
argmaxgpt-oss + Gemma 3

Finds the highest logit of 201,088 with deterministic tie-breaking.

Shows: thread, warp and block levels; a planted tie resolved to the smaller index.
1 block · 1024 threads
compact_logitsgpt-oss + Gemma 3

Keeps only logits near the maximum so the host sorts hundreds of candidates instead of the vocabulary.

Shows: the threshold moving with temperature, atomic append, the host's fallback ladder.
