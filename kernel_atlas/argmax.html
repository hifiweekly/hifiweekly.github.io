Inside argmax

Greedy decoding picks the token with the largest logit out of the 201,088-entry vocabulary. The answer is a single index, and only the GPU has the logits, so one block of 1024 threads finds it and the host copies back 4 bytes instead of 786 KB. Ties go to the smaller index, which makes the result independent of thread timing and matches a plain CPU loop.

out = min { i : x[i] = maxj x[j] }   // pairs (value, index) compared as: larger value wins, equal values → smaller index

Why it is built this way

    

      

        
Tie-breaking at every level

        
In the scan, a thread replaces its best only on setp.gt (strictly greater). Its elements come in increasing index order, so it keeps the first of equal values. In the butterflies, a partner's pair wins if its value is greater, or equal with a smaller index. Each level therefore returns the smallest index among the maxima, and so does the whole reduction, whatever order the hardware runs warps in.

      

      

        
Why a single block

        
The vocabulary is read once: 786 KB. A single block of 1024 threads reads it with coalesced loads in about 197 rounds. More blocks would need a second launch or global atomics to combine their results, and decode runs this once per token. With greedy decoding, the host then copies only the 4-byte index.
