SAM 3 (image, text prompt)

Meta's Segment Anything 3, the first vision model in this atlas. Given an image and a noun phrase it returns every instance of the phrase: a box, a score and a mask each. It has two encoders: a ViT-L over 72 × 72 patches of the 1008-pixel image, and a CLIP text transformer over the prompt. A fusion encoder lets the image tokens attend to the prompt, and a DETR-style decoder turns 200 learned queries into boxes, refined after every layer. A dot product with the pooled prompt scores each query, gated by a presence token, and a pixel decoder plus a per-query embedding gives each query a 288 × 288 mask. The engine runs it with 21 new kernels; every matrix product is one tensor-core GEMM (gemm_f16) and every attention one flash-attention kernel (flash_attn). What is new in sam3.ptx

Everything: hashing every .entry with its comments stripped against the eight other files finds no shared kernel. The language-model engines decode one token at a time with quantized matrix–vector products. SAM 3 runs thousands of tokens per product, so it is built around two tensor-core kernels and a set of small reshaping kernels that feed them.

The 21 kernels

Convolutions as products

The neck and the pixel decoder are convolutions, and the engine has no convolution kernel: each becomes a matrix product. A 3 × 3 convolution reads im2col3's matrix (each row the 9 × 256 neighbourhood of a pixel, in the weight's [out][ky][kx][in] order). A 1 × 1 convolution is a product of the feature map as it is. A 2 × 2 stride-2 transposed convolution is a product to 4 · out columns, which depth2space scatters to the doubled map. The weights are stored MLX-style, [out][kh][kw][in], so every weight is already the B operand of gemm_f16.

Hashed tensor names

The GGUF (converted from the MLX port of facebook/sam3) names its 1368 tensors t_ + 12 hex digits: the start of SHA-1 of the PyTorch parameter name, with nn.MultiheadAttention's in_proj split into query, key and value. sam3.c carries a SHA-1 and hashes the names it needs. Every one of the 1122 tensors of the image model was checked bit-equal to the PyTorch checkpoint.

Not a language model

There is no KV cache, no sampling, no decode step. A prompt costs 24 ms after the image's 95 ms, because the image features are computed once and reused. The CLIP tokenizer is the only text-side code. Its merges come from CLIP's vocabulary file, since the GGUF has none, and its cleaning matches the Python code's (ftfy's character fixes, Unicode lower-casing).

Tensors of one layer of each kind, plus the shared ones

PyTorch parameter names (the GGUF stores SHA-1 hashes of them). Shapes are rows × cols, output × input; convolutions as [out][kh][kw][in]. The file is f32. Matrices go to the GPU as f16, norms, biases and the small heads stay f32, and the text embedding stays in host memory.
