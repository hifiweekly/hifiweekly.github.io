Inside rmsnorm

RMSNorm rescales a token's hidden vector so its root-mean-square is 1, then multiplies by a learned weight per dimension. It runs before every attention and expert block. All 1024 threads of one block must agree on a single number, the row's sum of squares, so the kernel is mostly a lesson in reductions: a strided loop, a warp butterfly, then shared memory.

y[i] = x[i] · 1 / √(Σ x² / n + ε) · w[i]   // n = 2880, ε = 1e-5, f32 throughout

Why it is built this way

    

      

        
The butterfly instead of a tree in shared memory

        
A warp exchanges registers directly with shfl.sync.bfly. After five rounds (offsets 16, 8, 4, 2, 1) every lane holds the full warp sum, with no shared memory and no barrier. Only the 32 warp totals go through shared memory, so the whole kernel needs one bar.sync.

        
Because every lane ends up with the total, any lane could write it. Lane 0 does.

      

      

        
Every thread repeats the final sum

        
After the barrier, all 1024 threads add the same 32 partials and compute the same scale. That is 32 shared-memory reads each, but they are broadcasts (every thread reads the same address), and it avoids a second barrier that a "thread 0 computes, everyone waits" scheme would need.

        
The work is tiny next to the matrix products around it: per token, x is read twice and w once, and y is written once, about 46 KB of memory traffic. The second read of x usually hits in cache.
