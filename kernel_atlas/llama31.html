Llama 3.1 8B

The plain pre-norm decoder that the other models in this atlas vary: 32 identical layers, each an RMSNorm, grouped-query attention with rotary position embedding, a residual add, an RMSNorm, a SwiGLU feed-forward and a residual add. No sliding windows, no sandwich norms, no head norms, no gates, no experts. This page draws the dataflow of the GGUF file with the kernel the engine launches at each step; weight shapes and types come from the file header. Click any box for details.

What is new in llama31.ptx

The engine started as a copy of the Qwen 3.8 engine (qwen35.ptx generalized to every weight format of a 27B Unsloth file) with the DeltaNet kernels removed. Of its 10 kernels, 6 are byte-identical to qwen35.ptx's (after stripping comments) and have their pages already; 4 are new to the atlas. Mistral 7B v0.3 runs all 10 unchanged.

The kernels

Llama 3's RoPE scaling

Llama 3.1 was trained at 8,192 tokens and extended to 131,072 by slowing down only its slowest rotations. Each of the 64 rotary pairs has a fixed divisor, stored in the file as rope_freqs.weight: pairs 0–28 (wavelengths under 2,048 tokens) keep their frequency, pairs 35–63 (wavelengths over 8,192) turn 8 times slower, and pairs 29–34 blend the two. The host divides each angle by its factor while it builds the cos/sin table, so the kernel never sees the scaling; rope_kv plots the factors.

One cache, reused

Every layer keeps an f16 KV cache, 128 KiB per position over the 32 layers: 1 GiB at the default 8,192. With no recurrent state, any prefix the cache shares with a new prompt is still valid, so a chat turn only computes its new tokens (17 of 78 in a two-turn test) and editing earlier text recomputes from the first changed token. llama31_demo cache-test checks that extending, rewinding and single steps give bit-identical logits.

Tensors of one layer, plus the shared ones

Shapes are rows × cols, that is output × input, the way the kernels index them (the GGUF header lists them the other way round). Everything is Q8_0, embeddings and head included; the engine splits each 34-byte block into a q array (32 int8) and a d array (one f16), and stacks matrices that read the same input into one product.

Measured

RTX 4070 SUPER, both engines on the same Q8_0 file.

Speed

Decode reads all 7.95 GB of weights per token: at 55 tokens/s that is 440 GB/s of the card's 504, the same as llama.cpp. Prompt processing is 2.2× slower than llama.cpp's: the same gemm_q gap as in the Qwen engines (no double buffering, 64 × 64 tiles).
