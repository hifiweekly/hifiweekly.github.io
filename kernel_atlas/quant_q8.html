Inside quant_q8

The 4-bit and 5-bit expert and feed-forward weights are multiplied with integer dot products (dp4a), so the activation they meet has to be 8-bit integers too. quant_q8 converts a float vector into Q8 blocks: every 32 consecutive values share one float scale d, and each value becomes round(x / d), between −127 and 127. One warp handles one block, one lane per value, so the block's maximum comes from a five-step butterfly with no shared memory.

The kernel is the same PTX, byte for byte, in both engines. What differs is where it runs: gpt-oss calls it before the MXFP4 expert products, Gemma 3 before the Q5_0 feed-forward products. Pick a call site below; the data and sizes follow.

d = maxj<32 |xj| / 127    qj = round(xj · (1/d))   // in-place mode instead writes xj ← qj · d

Where it runs

Four launches per layer in decode, two per engine; in prefill the same two run in place. Selecting a row sets the data and grid on the rest of the page.

Why it is built this way

    

      

        
A warp is exactly one block

        
Q8 blocks are 32 values and a warp is 32 lanes, so the reduction for the scale never leaves registers: five shfl.sync.bfly + max pairs, no shared memory and no barrier. The loop condition depends only on the warp index, so whole warps leave together and the shuffles always have all 32 lanes.

        
The scale is computed once as d = amax / 127 with an IEEE division, then each lane multiplies by 1/d instead of dividing, as ggml's quantize_row_q8_0 does. An all-zero block gets d = 0 and 1/d forced to 0, so q = 0 instead of NaN.

      

      

        
The in-place ("fake") mode

        
Decode uses int8 output: xq (1 byte per value) and xd (one float per block), read directly by mv_mxfp4 and mv_q5. The prefill GEMMs read float tiles instead, so the host passes q = 0 and the kernel overwrites x with q · d. The GEMM then sees exactly the values the int8 path would have used, which keeps decode and prefill outputs consistent.

        
Rounding is cvt.rni: to nearest, ties to even. The error per value is at most d / 2, about 0.4% of the block's largest value.
