GLM-4.6V-Flash (language model)

The 9.4B text decoder of Zhipu's GLM-4.6V-Flash vision-language model (GGUF architecture glm4; the engine runs text only, without the vision encoder). Its layer is Llama 3.1's with four changes: an RMSNorm also after each sub-layer, before the residual add, as in Gemma 3; biases on the q, k and v projections; only 2 key/value heads for 32 query heads; and rotary embedding on the first 64 of each head's 128 dims, in NeoX pairs. The engine runs it with Llama 3.1's kernels, Gemma 3's fused add_rmsnorm and one new kernel, bias_rope_kv. This page draws the dataflow of the GGUF file with the kernel the engine launches at each step; weight shapes and types come from the file header. Click any box for details.

What is new in glm46v.ptx

The engine started as a copy of the Llama 3.1 engine. Hashing every .entry with its comments stripped against the other engines: of its 11 kernels, 9 are byte-identical to llama31.ptx's, add_rmsnorm is byte-identical to gemma3.ptx's, and one is new, bias_rope_kv.

The kernels

Sandwich norms, fused as in Gemma 3

Each sub-layer ends with x += rmsnorm(y) · post_norm, and the next step starts with xn = rmsnorm(x) · pre_norm. Gemma 3's add_rmsnorm does both in one launch per row: the sum of squares of y, then x += y · scale · w₁ while summing x², then xn. GLM-4 needs exactly that, so the output and down projections no longer add into x themselves: they write y, and two add_rmsnorm launches per layer replace Llama 3.1's two residual adds and two rmsnorms.

RoPE on half the head, from M-RoPE

The GGUF says rope.dimension_count = 64 and rope.dimension_sections = [8, 12, 12, 0]: GLM-4.6V's multimodal RoPE. Only dims 0–63 of each 128-dim head rotate, in NeoX pairs (i, i + 32), and pair i takes its angle from a temporal position (pairs 0–7), a height position (8–19) or a width position (20–31). An image patch has three different positions; a text token has the same one three times, so for text it is ordinary NeoX RoPE on 64 dims with θᵢ = pos · 500000−i/32, and dims 64–127 carry no position at all. bias_rope_kv steps through it.

2 key/value heads

32 query heads share 2 key/value heads, 16 each (Llama 3.1: 4 each). The KV cache is 2 × 2 × 128 f16 values per layer and position, 40 KiB over the 40 layers: 320 MiB at the default context of 8,192, a third of Llama 3.1's at the same length. The attention kernel is unchanged: q head h reads kv head h / 16.

Chat and thinking

Prompts start with [gMASK]<sop>; turns are <|system|>, <|user|> and <|assistant|> control tokens, and the model reasons inside <think> … </think> before it answers, unless the turn ends with /nothink. Its reply ends when it emits <|user|>. Earlier replies are rendered without their reasoning, so the KV cache is reused up to the end of the previous user message.

Tensors of one layer, plus the shared ones

Shapes are rows × cols, that is output × input, the way the kernels index them (the GGUF header lists them the other way round). The matrices are Q8_0, embeddings and head included; the engine splits each 34-byte block into a q array (32 int8) and a d array (one f16), and stacks matrices that read the same input into one product. Norm weights and biases are F32.
