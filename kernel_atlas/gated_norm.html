Inside gated_norm

After gdn_recur has read each DeltaNet head's state, the 32 head outputs o (128 values each) are normalized and gated before the output projection: an RMSNorm over each head separately, a learned weight shared by all heads, and a multiplicative gate silu(z), where z is a fourth projection of the layer input computed alongside q, k and v. One block handles one head of one token, so a thread owns one value and the only reduction is over 128 numbers.

out[j] = o[j] · 1 / √(Σ o² / 128 + ε) · w[j] · SiLU(z[j])   // per head of 128; w = ssm_norm.weight (128 values, all heads); ε = 1e-6

Where o and z come from

      
o is gdn_recur's output, 32 heads × 128 per token. z was produced much earlier, by the same matrix product as q, k and v (mv_q4_1 on the stacked [qkv ‖ z] matrix), so it sits in the last 4096 floats of each 12,288-float row of that buffer: the kernel reads it with a row stride of 12,288 (ldz) instead of copying it out.

    

    

      

    

  


  

    
Why it is built this way

    

      

        
A norm per head, not per token

        
Each head's state accumulates at its own scale: a head whose decay g stays near 1 keeps a much larger S than one that forgets quickly. Normalizing every head to unit RMS before mixing them in the output projection is a group norm with 32 groups. The weight w is shared, so it shapes the 128 dims of a head the same way in every head.

        
With a block per head, the reduction is 4 warp butterflies and a 4-entry shared array: one barrier, and every thread adds the 4 partials itself (one ld.shared.v4, a broadcast).

      

      

        
The output gate

        
SiLU(z) lets the layer input decide, value by value, how much of the recurrent read-out passes on. It is the same idea as the sigmoid gate on Qwen's full-attention outputs, applied here after the norm. SiLU uses one ex2.approx and one division, as in swiglu.

        
The kernel writes into xn, which quant_q8 turns into int8 blocks for the output projection (mv_q5_k).
