MiniMax-H3 · minimaxh3.ptx · flash attention read straight out of the fused q, k, v projection

Inside attn_d128

MiniMax-H3 has three kinds of attention: the diffusion transformer's 56 heads of 128 over the whole 541-token sequence, the text encoder's 64 query heads sharing 8 key/value heads, causal, and the video VAE's 32 heads of 64 over 1,797 tokens. Each network's q, k and v come out of one fused GEMM, and each lays them out differently. This kernel (and attn_d64, its 64-dim twin) reads every head from where the projection left it: a column offset for q, k and v, a stride between heads and a group size for shared key heads, so nothing is split or transposed in between. Inside it is a flash attention: 64 queries per block, key tiles through two cp.async buffers, S = QKᵀ and O += PV on f16 tensor cores, and the online softmax in base 2 with P never leaving registers.

O[t][h] = softmaxj(qt,h · kj,h/g / √d) · vj,h/g,   qt,h = qkv[t][qoff + h·hstride …], k, v likewise at koff, voff   // causal: j ≤ t

Why it is built this way

    

      

        
No split-heads kernel

        
SAM 3's engine copies q, k and v into per-head arrays before flash_attn. Here the loader computes each head's columns itself, so the three networks' fused projections are read as they are: [q₀ … q₅₅ | k₀ … k₅₅ | v₀ … v₅₅] in the diffusion transformer, [q₀ … q₆₃ | k₀ … k₇ | v₀ … v₇] with 8 query heads per key head in the text encoder, and [q k v]₀ … [q k v]₃₁ interleaved per head in the video VAE, which reshapes its projection to (3 · 64, 32 heads) before chunking. The only cost is a 256-byte (or 128-byte) row of a head being one strided segment of a long row, which cp.async reads 16 bytes per thread just as well.

        
Zero-filled tails, not bounds checks

        
The 541st key is the last; the 17th tile has 3 rows past it. cp.async with a source size of 0 writes zeros into shared memory for those rows, and the scores of keys ≥ N are set to −∞ before the softmax, so the inner loop has no branch per key. Query rows ≥ N are computed and not stored.

      

      

        
Small share of the time

        
Attention is 1.1% of the diffusion transformer's GPU time (131 µs per block against 12 ms for the products) and 6% of the video VAE's (15 ms of a 255 ms chunk, 36 launches of 0.42 ms). The sequences are short next to the width: 541 tokens × 56 heads × 128 is 8.4 GFLOP per block for QKᵀ and PV together, against 417 GFLOP for the block's four products.

        
The text encoder is causal

        
With causal set, a block only visits key tiles up to its last query, and scores with key > query are −∞. The text encoder runs one block of 64 queries per head for the 19-token prompt; group 8 makes 8 query heads read the same key and value columns. The VAE variant, attn_d64, keeps 64-key tiles (64-dim rows are half as wide, so a tile is the same 8 KB).

        
Scale and base 2

        
Scores are multiplied by (1/√d) · log₂e once, so the softmax uses ex2.approx directly: 2s − m is e(qk/√d) − m′. The reference applies a 1/128 "kv_scale" to k and v and undoes it after flash attention, a guard against f16 overflow in its kernel; mathematically it is the same softmax, and the row maxima here keep every exponent ≤ 0.
