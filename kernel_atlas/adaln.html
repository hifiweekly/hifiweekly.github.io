Inside adaln

Every one of MiniMax-H3's 50 diffusion blocks modulates its two norms and gates its two residual adds with vectors computed from the timestep: shift, scale and gate for attention, the same three for the feed-forward, separately for video, text and audio tokens. That is 6 × 3 × 5376 = 96,768 numbers per block. The model computes them from just 8 numbers: a learned curve, adaln_t_table, tabulated at 1025 points of t ∈ [0, 1], stands where other diffusion transformers have a sinusoidal embedding and an MLP. Each block's vectors are an affine function of those 8 numbers. This kernel evaluates all of them, for all 50 blocks and every timestep the sequence uses, at the start of each sampling step: 4.8 million threads, one launch.

out[(l·R + r)·J + j] = b[l·J + j] + Σi<8 W[l·J + j][i] · temb[r][i],   temb[r] = lerp(table, 1024 · tr)   // J = 96,768 per block, L = 50 blocks, R ≤ 4 timesteps

Why it is built this way

    

      

        
A table instead of a time MLP

        
Diffusion transformers usually embed the timestep with sinusoids, run it through a two-layer MLP, apply SiLU, and only then project it to each block's modulation. In this checkpoint the first part is gone: adaln_t_table holds the 8-dimensional embedding at 1025 evenly spaced t (the "AdaLN curve"), and the engine interpolates linearly between the two rows around 1024 · t, on the host, for at most 4 timesteps per step. Only the last, affine part remains, and that is this kernel. The curves are smooth and dominated by the first two components: the time signal the network sees is low-dimensional by construction.

        
Four timesteps, three used

        
The sequence carries the video timestep (text and video tokens) and the audio one, which follows its own sigma schedule (shift 3 instead of 12), plus two rows the reference adds for reference-media conditioning. The engine keeps all four so its row numbering matches, deduplicates equal values (at the first step all are 0 or 0.999), and evaluates every row: the cost is in reading W, not in the rows.

      

      

        
Memory-bound, once per step

        
Each thread reads 8 f16 weights (one 16-byte load) and a bias, then does 8 FMAs per timestep row: 77 MB of weights in, 58 MB of f32 vectors out (3 rows), about 0.2 ms of the 610 ms step (nsys). Computing a block's vectors inside the block would read the same bytes; doing all 50 at once keeps the launch count down and leaves the vectors in one array, [block][timestep row][modality][6][5376], where rms_mod and gemm_f16's gated epilogue find them by (timestep row × 3 + modality) and a stride of 6 · 5376.

        
What the vectors do

        
Gates grow with depth: block 0's are a few tenths, block 49's attention gate for video has an rms above 4. Shift and scale vary little with t compared with the gates, so most of the time dependence enters through how strongly each block's output is added. Block 49's text gates and feed-forward modulation are exactly zero: nothing reads text rows after the last block. The final layer's own (shift, scale) pair is a second, single-block launch of the same kernel.
