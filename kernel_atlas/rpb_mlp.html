Inside rpb_mlp

In SAM 3's decoder each of the 200 queries carries a box, refined after every layer. When the queries attend to the 5184 image tokens, every query–token score gets a bias that depends on where the token lies relative to the query's box. Keys inside the box are favoured and keys far outside are pushed down: the box relative position bias ("boxRPB", log mode). Computed naively, that is 8 heads × 201 queries × 5184 keys per layer. It is separable, though. A small MLP maps the token column's distances to the box's left and right edges to 8 head biases, a second MLP does the same for rows, and the bias of a key is the sum of its row's value and its column's value. This kernel evaluates the two MLPs for every query and every one of the 72 grid lines. flash_attn adds by[row] + bx[column] to each score. The weights on this page are the model's own (boxRPB_embed_x, boxRPB_embed_y).

d = (i/72 − x₀, i/72 − x₁),  d̂ = sign(8d) · log₂(8|d| + 1) / 3,  bx[h][q][i] = W₂ relu(W₁ d̂ + b₁) + b₂   // rows likewise with y₀, y₁; score(q, key) += by[h][q][key / 72] + bx[h][q][key % 72]

2 axes × 72 grid lines × 200 queries: 28,800 threads per layer

A thread takes one query, one axis and one grid line i (a column for x, a row for y). It turns the query's box (cx, cy, w, h) into edges, computes the line's two distances to them, squashes them, runs them through the axis's MLP (256 hidden units, 8 outputs, one per head) and stores the 8 values. Set the box and pick a head; the map shows the bias each key gets for that head.

Why it is built this way

    

      

        
A bias that is a sum

        
PyTorch builds the bias as B[q][y][x][h] = Ey[q][y][h] + Ex[q][x][h], then flattens it to a [8 × 201][5184] float mask for nn.MultiheadAttention: 33 MB written and read per decoder layer. The engine keeps the two factors, 8 × 201 × 72 floats each (463 KB), and lets the attention kernel add the two terms of each score. A query's row and column entries are a few hundred bytes that stay in L1 across the 64-key tiles. The decoder's attention costs about the same with the bias as without it.

        
The squash

        
The distances are fractions of the image (−1 … 1). Multiplied by 8 and passed through log₂(|·| + 1) / 3, a whole image maps to 1.06. The curve is 9 times steeper at the box edge than a full image away from it. One patch (1/72) moves d̂ by 0.05 at the edge and by 0.006 at the far side, so the MLP resolves the edges of the box finely and cares little about exactly how far a distant key is. The sign survives, so inside (d₀ > 0, d₁ < 0) and outside on either side are distinguishable.

      

      

        
One thread, eight outputs

        
The first layer has 2 inputs, so each hidden unit is two FMAs and a max. The second layer is 8 FMAs per hidden unit, accumulated in 8 registers as the thread walks the 256 units, so the hidden layer never needs storing. Per thread that is 256 × 11 operations and 2.6 K weight loads. All threads of a warp read the same weight at the same time, a broadcast from L1. 28,800 threads take 40 µs per layer.

        
Row 0 is the presence token

        
The decoder's sequence is the presence token followed by the 200 queries. The presence token has no box and its row of the mask is zero (torch.zeros_like(cross_attn_mask[:, :1, :])), so query q writes row q + 1 and row 0 stays as allocated, zero. The boxes the bias is computed from are the ones entering the layer. They are detached in the reference, which matters for training only.
