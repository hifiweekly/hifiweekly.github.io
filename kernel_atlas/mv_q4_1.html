Qwen 3.5 · qwen35.ptx · decode: one warp per row, Q4_1 weights × int8 activations

Inside mv_q4_1

Almost every Qwen 3.5 matrix in the Unsloth file is Q4_1: 4-bit integers with an f16 scale and an f16 offset per 32 values, 5 bits per weight. When decoding, this kernel reads 4 of the 5 GB that each token needs, so it sets the speed: about 460 GB/s of the card's 504. It multiplies a matrix by the token's activation, which quant_q8 has turned into int8 blocks with a scale d and a precomputed d · Σq. That second number is what makes the offset free.

y[r] = Σb ( d·dₓ · Σj<32 qjxj  +  m · dₓΣjxj ) + resid[r]   // weight = d·q + m, q in 0…15; activation = dₓ·x, x int8

One lane, one Q4_1 block

A block is 16 bytes of nibbles (qs) and 4 bytes of scale and offset (dm, two f16), kept in two arrays. Byte i holds value i in its low nibble and value 16 + i in its high nibble. Step through how a lane gets 32 products with 8 integer instructions, then two float multiply-adds for the whole block.

Why it is built this way

    

      

        
Unsigned nibbles, signed activations, one offset term

        
Q4_1 stores q = (w − m) / d, an unsigned 0…15, so the nibbles go straight into dp4a.u32.s32 (unsigned weights, signed int8 activations) after one mask or a shift and a mask: no −8 correction as in Q4_0, no fifth bit as in Q5_0.

        
The offset multiplies the sum of the block's activations, Σ (d q + m) dₓx = d dₓ Σ q x + m · dₓ Σ x. quant_q8 already stores dₓ Σ x next to dₓ (it sums the int8 values once per block), so the offset costs one FMA per 32 weights. The integer sums are exact; there are two roundings per block, plus the reduction.

      

      

        
Memory: what the kernel is really about

        
A block is 20 bytes for 32 weights. In the GGUF they are contiguous; 20 is not a multiple of 16, so the loader splits them into a qs array (16 B per block, read with one ld.global.nc.v4.u32) and a dm array (4 B per block). A warp then reads 512 consecutive bytes of qs and 128 of dm per round: every byte of each 32-byte sector is used.

        
Rows that read the same input are stacked at load time ([qkv ‖ z], [q|gate ‖ k ‖ v], [gate ‖ up]): one launch and one pass over x instead of two or three. The residual add is folded in: the output projections pass x as both resid and y.
