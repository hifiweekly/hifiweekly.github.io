Inside head_norm_rope

After the Q/K/V products, every head of every token is RMS-normalized on its own. Query and key heads are then multiplied by their norm weights and rotated by the token's position (RoPE, NeoX layout); value heads are only normalized, with no weight. Unlike Gemma 3's qk_norm_rope, the same kernel must handle 256-dim heads (local layers) and 512-dim heads (global layers), there is no KV cache to write, and the position comes from a per-token array because one batch packs several texts.

x' = RoPEpos[t]( x / √(Σ x² / D + ε) · w )   // pairs (i, i + D/2); v heads: x / √(Σ x² / D + ε) only

The grid: one block per head per token

A local layer's token holds 4 query, 2 key and 2 value heads of 256 floats (grid.x = 8); a global layer's holds 4 query, 1 key and 1 value head of 512 floats (grid.x = 6). grid.y is the token. The position is the token's offset in its own text, not in the batch: the strip below packs three texts, and the position restarts at each one.

Inside one head

The head is drawn as two rows: dims 0 … D/2−1 on top and D/2 … D−1 below, so each rotation pair (i, i + D/2) is one column. Thread i owns column i, and for 512-dim heads column i + 128 as well: every pair stays inside one thread for both head sizes. Click a column to follow its thread.

Why it is built this way

    

      

        
One kernel for two head sizes

        
Gemma 3's qk_norm_rope gives a whole 256-dim head to one warp: lane l holds dims 4l…4l+3 and their partners, eight registers, no shared memory. That layout is tied to D = 256. Here a block of 128 threads walks the pairs with a stride of 128: thread i takes pair i, then pair i + 128 if the head has one. The partner of every value is still in the same thread, so the rotation needs no shuffles, and D = 256 and D = 512 run the same code with one or two trips around the loop.

        
The price is a 4-warp reduction (butterfly, then 4 partials through 16 bytes of shared memory and one barrier) and reading the head twice, once for Σx² and once to apply. The second read of 1–2 KB per head hits in L1.

      

      

        
What the weights do here

        
This model leaves out the usual 1/√d on the attention scores (scale 1.0). Its norm weights take that role: every value of attn_q_norm is about 1.02, and every value of attn_k_norm is the same constant, 0.122 in local layer 0 and 0.063 in global layer 5. So q has RMS ≈ 1, k has RMS ≈ 0.1, and q·k lands in a range softmax can use. The page uses those real constants.

        
V heads get an RMS norm without any weight, which llama.cpp writes as a bare ggml_rms_norm; the kernel skips the weight load and the rotation for them with one uniform branch.
