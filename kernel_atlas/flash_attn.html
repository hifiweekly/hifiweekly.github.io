Inside flash_attn

All attention in SAM 3 runs in this kernel. That covers the ViT's windowed and global self-attention, the text encoder's causal attention, the fusion encoder's 5184 × 5184 self-attention and its cross-attention to the prompt, the decoder's three attentions (the image one with a relative position bias per query box), the geometry token and the segmentation head. It is a flash attention. For a block of 64 queries it walks over the keys in tiles of 64, computes the scores of a tile with tensor-core mma, updates a running maximum and sum per query row, rescales its output accumulators, and adds the tile's probabilities times its values. The score matrix never exists in memory, so a 5184-key attention needs no more shared memory than a 64-key one.

O = softmax(QKT · scale + bias) V:   per tile, m′ = max(m, maxj sj),  l′ = l · 2m − m′ + Σj 2sj − m′,  O′ = O · 2m − m′ + P V   // s in base 2: s = (q · k · scale + bias) · log₂e

One block: 64 queries of one head, the keys 64 at a time

blockIdx.y is the (batch or window) × head, blockIdx.x a group of 64 queries. Each of the 4 warps owns 16 query rows for the whole kernel. Every thread holds 2 of those rows (g = lane / 4 and g + 8) and, per key tile, 16 scores of each. Pick a use of the kernel. Why it is built this way

    

      

        
One kernel, seven attentions

        
SAM 3 attends in many shapes: 576-token windows and 5184-token global blocks of 64-dim heads, 5184 × 5184 with 32-dim heads, 201 queries over 5184 keys, 5184 queries over 33 prompt tokens, 32 causal text tokens, one CLS query. Instead of a kernel per shape, the layout is fixed: Q, K and V are f16 [batch × head][rows][64] with rows padded to 64. The parameters cover the rest. lq and lk say which rows are real. flags select a key mask, causality or the box bias. dout and ostride say where the output columns go, and wsz, nwx and gw undo the window partition when the result is stored. 32-dim heads are zero-padded to 64 by split_heads. The padding adds 0 to every score and its output columns are not stored, so the cost is twice the mma work of the fusion encoder's attention, about 4 ms per image.

        
The masks cost nothing when unused

        
A full tile with no flags (every ViT tile, every fusion-encoder self-attention tile) only multiplies its 32 scores by scale · log₂e. The general path calls mask_score for each score. It sets a padding key (index ≥ lk) to −∞, then a masked key (flags 1: the prompt's padding tokens), then a later key (flags 2: causal). Last it adds the box bias (flags 4). The bias is separable: by[h][q][key row] + bx[h][q][key column] over the 72 × 72 grid of image tokens, two loads instead of a 5184-entry row per query (rpb_mlp builds it). A row whose keys so far are all masked keeps m = −∞; the rescale then subtracts 0 instead, so no NaN appears.

      

      

        
P stays in registers

        
The S accumulator of an m16n8 mma holds, per lane, rows g and g + 8 at columns 2t and 2t + 1 of 8 keys. The A operand of an m16n8k16 mma wants rows g and g + 8 at k = 2t, 2t + 1 and 2t + 8, 2t + 9. So the accumulators of two adjacent 8-key tiles, converted to f16 pairs (cvt.rn.f16x2.f32), are exactly the A fragment for those 16 keys. The probabilities go from the softmax into the P·V mma without touching shared memory. V is stored [key][dim] and the mma needs it as the "col" operand, so it is read with ldmatrix.trans, which transposes 8 × 8 tiles on the way into registers.

        
Shared memory and occupancy

        
Q (8 KB) is loaded once and kept in 16 registers per thread. K and V tiles take 8 KB each and are double-buffered: the next tile's cp.async copies run under this tile's mma work. That is 40 KB per block, and with 128 threads and 162 registers each, several blocks fit on an SM. Rows are 128 bytes, and chunk c of row r is stored at c ^ (r & 7), so every ldmatrix phase hits 8 different bank groups. Softmax runs in base 2 with ex2.approx: the scale is multiplied by log₂e once, and an exponential costs one instruction. Attention is about 20% of the engine's GPU time, mostly the ViT's 4 global blocks.
