Qwen 3.5 9B

A hybrid model: three of every four layers replace attention with a Gated DeltaNet, a linear-attention layer that keeps a 128 × 128 matrix per head instead of a growing KV cache; the fourth is a gated full-attention layer. This page draws the dataflow of the GGUF file with the kernel the engine launches at each step. Weight shapes and types come from the file header; each operation is named after its PTX kernel. The Gated DeltaNet

What the three new kernels compute, per token t and value head h (32 heads of 128; queries and keys come from head h mod 16, llama.cpp's mapping).

q, k, v = silu(conv1d₄(Wqkv·x))  ·  q, k ← q/‖q‖, k/‖k‖  ·  β = σ(Wβ·x)  ·  g = exp(softplus(Wα·x + dt) · a)
S ← g·S + k·((v − g·Sᵀk) β)ᵀ  ·  o = Sᵀq / √128  ·  y = Wout·(rmsnorm(o) · w · silu(Wz·x))

The kernels

State instead of a cache

A DeltaNet layer carries a fixed 2 MB (32 heads × 128 × 128 f32) plus its conv state (the last 3 inputs, 96 KB), whatever the context length. Decoding a token reads and writes it once: 96 MB per token over the 24 layers, about 2% of the 5 GB of weights. Only the 8 attention layers keep an f16 KV cache: 32 KB per position, a quarter of what 32 attention layers would need.

The state can't be rewound. A KV cache is valid for any common prefix of a new prompt, but S holds exactly the tokens it has seen. So a chat copies all 24 states (50 MB, GPU to GPU) at the end of <|im_start|>assistant\n, where the next turn's prompt will diverge (earlier replies are re-rendered without their thinking block), and the next turn restores the copy and recomputes from there. qwen35_demo cache-test checks that extending, restoring and recomputing give bit-identical logits.

Tensors of one layer, plus the shared ones

Shapes are rows × cols, that is output × input, the way the kernels index them (the GGUF header lists them the other way round). The Unsloth Q4_1 file mixes four quantized types; the engine keeps each as stored, with the fields of the 32-value types in separate arrays. A BF16 file is converted to Q8_0 while loading.

Measured

RTX 4070 SUPER, 1,282-token prompt, greedy decoding, both engines on the same Q4_1 file.

Speed

Decode reads 5.0 GB of weights per token; mv_q4_1 and mv_q6_k run at 460 and 470 GB/s of the card's 504. Prefill time goes to the GEMM (73%), the token-by-token recurrence (12%) and attention (8%); llama.cpp's matrix kernels use larger tiles, and its recurrence and attention run on the tensor cores.
