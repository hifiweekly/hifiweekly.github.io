gpt-oss · gptoss.ptx · decode: 4 experts per token, one warp per row

Inside mv_mxfp4

Each gpt-oss layer has 32 experts, and each expert has three 2880 × 2880 matrices (gate, up, down) stored in MXFP4: 4-bit floating-point codes with one shared power-of-two scale per 32 values. In decode a token uses only 4 experts, so mv_mxfp4 multiplies the token by just those 4 matrices: the grid's y index is the expert slot, and the expert id comes from router_topk. It runs three times per layer; pick which one below.

y[s][r] = Σb 2e[b] − 128 · xds[b] · Σj<32 fp4×2(code[r][32b+j]) · xqs[32b+j] + biasE[r]   // E = ids[s]

Which weights are read

One lane, one MXFP4 block of 32 weights

Lane b of a warp takes blocks b, b + 32, b + 64 of its row (90 blocks of 32 values; lanes 26–31 skip the third round). A block is 16 bytes of codes plus one scale byte. Step through how a lane turns them into one float term: split nibbles, decode four codes at a time with byte permutes, multiply with the int8 activation using dp4a, scale.

Why it is built this way

    

      

        
Integer dot products on 4-bit floats

        
An E2M1 value is one of ±{0, 0.5, 1, 1.5, 2, 3, 4, 6}. Doubled, every one is an integer that fits in a signed byte, so after decoding, four weights and four int8 activations go through one dp4a (4 multiplies and adds in one instruction). The doubling is undone by using 2e−128 instead of the format's 2e−127.

        
The decode itself is three prmt byte permutes per four codes: the low 3 bits of each code index a byte of {0,1,2,3,4,6,8,12} or of its negated copy, and the sign bit picks which. No lookup table in memory, no branches.

      

      

        
Reading 4 of 32 experts

        
Each expert matrix is 2880 rows × 90 blocks × 17 bytes = 4.4 MB, so a decode step reads 3 × 4 × 4.4 = 53 MB of expert weights per layer instead of 423 MB. The activation was quantized by quant_q8 just before: gate and up share one input vector (xstride = 0), while down gives every slot its own (xstride = 2880), the swiglu output of that expert.

        
The engine keeps MXFP4 exactly as stored in the GGUF, only split into a code array and a scale array so the 16 code bytes of a block load as one aligned v4.u32.
