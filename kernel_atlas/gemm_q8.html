Inside gemm_q8

This kernel multiplies a batch of token activations by an 8-bit quantized weight matrix. The prompt-processing path calls it for every attention projection. Pick a block, pick a thread, and step through one launch to see exactly which bytes each of the 256 threads moves and multiplies.

Y[t][r] = Σc W[r][c] · X[t][c] + bias[r] + resid[t][r]   // W: int8 with one f16 scale per 32 columns · X, Y: f32

The grid: one block per 64 × 32 output tile

The output Y has one row per token and one column per weight row. The launch cuts it into tiles of 64 weight rows × 32 tokens, and each block computes one tile. The example problem has 2880 × 2880 weights and 77 tokens, the same shape as the GPU test that compared this kernel against its CUDA C++ rewrite. Select a tile to look inside it. The bottom row of tiles is only partly filled because 77 is not a multiple of 32.

Inside one block

The block walks along the shared dimension 64 columns at a time. In each k-step, the threads copy a 64 × 64 slice of weights and a 32 × 64 slice of activations into shared memory, wait for each other, multiply, and wait again. After the last step they add bias and residual and write the tile. The three panels are laid out as a matrix product: Xs (left) × Ws (top) accumulates into the Y tile.

Ws [64 k][64 rows]shared · f32 · 16 KB
Xs [32 tokens][68]shared · f32 · 8.5 KB
Y tile [32 tokens][64 rows]registers → global
