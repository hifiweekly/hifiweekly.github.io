02

gpu_in_five_minutes

Every kernel page draws threads as a grid of warps × lanes. Here is what that grid means.

A block of threads

A kernel is one function that thousands of threads run at once, each on different data. Threads come in warps of 32 that execute in lockstep. Warps are grouped into blocks that share fast on-chip memory, and the grid is all the blocks of one launch. Click a thread.

Rows are warps, columns are lanes, the same layout as the canvases on rmsnorm and mv_q8.

Where data lives

memorywho sees itwhy kernels care
registersone threadFastest. Each thread's running sums and loaded values. %f2 in PTX is a register.
warp shuffle32 lanes of a warpLanes read each other's registers with shfl.sync, with no memory involved. This is how most reductions start.
sharedone blockSmall and on-chip. Warps pass partial results through it and wait for each other at bar.sync.
globalevery threadThe GPU's main memory (gigabytes). Weights and the KV cache live here. Reading it is the bottleneck in decode, so access patterns matter: coalesced loads let a warp's 32 reads arrive as one transaction.

Reading one line of PTX

PTX is NVIDIA's assembly-like virtual instruction set, one step below CUDA C++. The driver compiles it to the GPU's machine code. Pick an instruction, then hover its parts.
