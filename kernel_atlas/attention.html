Inside attention

For one query head of one token, this kernel scores every visible cached key, turns the scores into softmax weights and sums the value vectors with those weights. It never stores the scores: each of its 8 warps walks its own share of the keys with an online softmax, keeping only a running maximum, a running sum and a 256-float accumulator, and the 8 partial results are merged at the end. Local layers see only the last 1024 positions, read from a ring buffer.

out = Σj=lo…p softmaxj(q · kj / 16) · vj   // lo = p − 1023 on local layers (when p ≥ 1024), else 0; scores kept in log₂ units

Eight warps, two keys at a time

Each column of the grid below is one loop step. Each row is a key slot within the step: rows 0–7 are key i of warps 0–7, rows 8–15 are key i + 8 of the same warps. So warp w owns rows w and w + 8, and relative key index = 16·step + row. Within a warp, lane l owns dims 8l to 8l+7 of q, k, v and the accumulator. Why it is built this way

    

      

        
Online softmax

        
Softmax needs the maximum score before it can exponentiate, which would mean two passes over the keys. Instead each warp keeps m (largest score so far), l (sum of 2s − m) and acc (sum of 2s − m·v). When a larger score arrives, the old l and acc are multiplied by 2m_old − m_new. The result is exact up to rounding, and the keys are read once.

        
Scores are scaled by log₂e up front (folded into q), so every exponential is a single ex2.approx.

      

      

        
Two keys per step, 8 warps per block

        
A step's two dot products are independent, so their two butterflies interleave and hide each other's shuffle latency. Each key costs 1 KB of K and V traffic (f16), and the 8 warps keep 16 keys in flight per block. Grouped-query attention means q heads 2h and 2h + 1 read the same kv head h, so the second read usually hits in L2.

        
The merge needs 8 KB of shared memory for the 8 accumulators, and the final division happens once per dimension: thread d writes out[d].
