MiniMax-H3 · minimaxh3.ptx · SAM 3's tensor-core GEMM with an AdaLN epilogue: a gate per row's segment

Inside gemm_f16 (MiniMax-H3)

Every matrix product of the four MiniMax-H3 networks runs in this kernel: 128 × 128 tiles of f16 mma.m16n8k16 with f32 accumulators, operands staged through a 3-stage cp.async ring with an XOR swizzle. That main loop is byte-for-byte SAM 3's gemm_f16, walked through on its own page. What is new is the epilogue: the accumulator is scaled by alpha, and a fifth mode adds the product into the residual stream multiplied by a gate that depends on the row's segment. That one multiply is AdaLN's gated residual: x += gate[seg] ⊙ (h · Wᵀ), for text, audio and video tokens in one launch. In the diffusion transformer the weights arrive as f16 slices that dequant_q4k has just expanded, so a block of the transformer is a chain of (dequant, GEMM) pairs.

v = acc · α + bias[col];   mode 0: C = v (f32) · 1: C = f16(v) · 4: C += v · 5: C += v · gate[seg[row] · gld + col]   // two adjacent columns per call of store_pair; rows ≥ M dropped

Why it is built this way

    

      

        
The gate where the sum is formed

        
AdaLN multiplies each sub-layer's output by a per-channel gate before the residual add, and the gate differs by token kind. Done separately, the product would be written, read back, gated and added: two more passes over a 541 × 5376 f32 matrix per sub-layer. In the epilogue the gate costs one byte load per row (seg) and one 8-byte load per pair of columns (two gates), and the residual add reads and writes the stream once, as mode 4 already did. Every product that adds into the stream, out_proj and fc2 of the 50 blocks (100 per step), is gated.

        
alpha keeps f16 in range

        
The feed-forward's hidden activations exceed f16's 65,504 in the deeper blocks. The reference scales fc1's input by 1/128 and its output back; here fc1 runs with α = 1/128 and an f16 output (mode 1), swiglu undoes the scale on input and re-applies it on output, and fc2 runs with α = 128 into the stream (mode 5). The video VAE does the same, with its fc1 bias pre-scaled on the host, since the bias is added after α.

      

      

        
541 rows, 640 computed

        
A block tile covers 128 rows, so 541 tokens take 5 row tiles and the fifth holds 29: 15% of the MMA work is on rows the epilogue drops. The column tiles are full (every N here is a multiple of 128). The q, k, v slice of 6,144 columns is 48 × 5 = 240 tiles on 56 SMs: 760 µs for 35.7 GFLOP, 47 TFLOPS counting only the real rows, 55 over the computed tiles.

        
Dequant, then GEMM, slice by slice

        
A slice's f16 weights (≤ 64 MB) are written by dequant_q4k and read by the next launch on the same stream, mostly from L2 for the first tiles. The pair takes about 1 ms per 6,144 columns of a 5376-wide matrix: 24% expanding, 76% multiplying. Fusing the decode into the B-tile loader would save the f16 round trip but decode each weight 5 times (once per row tile), and slow the inner loop the tensor cores are waiting on.

        
The other networks

        
The text encoder (19 tokens: one row tile, mostly empty) uses modes 1 and 4; the video VAE (1,797 tokens) runs f16 weights straight from the file with biases, modes 1, 0 and 5 (its per-channel layer scales are mode 5 with no segments: one gate row for all tokens); the audio VAE's convolutions are GEMMs on im2col matrices, with zero-padded rows and columns where its channel counts drop below 128 (col2im_t).
