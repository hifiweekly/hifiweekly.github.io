Mistral 7B v0.3

Mistral 7B Instruct v0.3 is stored in its GGUF as the llama architecture, and its layer has exactly the shapes of Llama 3.1 8B's: 32 identical layers, each an RMSNorm, grouped-query attention with rotary position embedding, a residual add, an RMSNorm, a SwiGLU feed-forward and a residual add. What differs is around the layers: a 32,768-token SentencePiece vocabulary (a quarter of Llama 3's, so 0.8 GB less of embeddings and head), plain RoPE of base 10⁶ with no frequency factors, and the [INST] chat format. The engine runs Llama 3.1's kernels unchanged. This page draws the dataflow of the GGUF file with the kernel the engine launches at each step; weight shapes and types come from the file header. What is new in mistral03.ptx

No kernel: mistral03.ptx is llama31.ptx with its header comment changed, and all 10 kernels are byte-identical after stripping comments, so each links to the page it already has. The engine's new parts are on the host.

The kernels

RoPE without scaling

v0.3 has a 32,768-token context and reaches it with the base alone: θ = pos · 10⁶−2i/128, so the slowest of the 64 pairs turns once every 5.1 million tokens (Llama 3.1's base of 5·10⁵ needs the ÷8 factors of rope_freqs.weight on top). The file has no factor tensor, and the host builds a plain cos/sin table; rope_kv reads it the same way. v0.3 also has no sliding window: v0.1's 4,096-key window was dropped in v0.2, so every layer attends over the whole cache.

SentencePiece and the chat format

The tokenizer is SentencePiece BPE with byte fallback, the Gemma 3 engine's, plus the one rule llama.cpp adds for this vocabulary: each run of text at the start or after a control token gets a leading "▁", so "Hi" is ▁Hi. The chat is built as token ids, the way Mistral's own tokenizer does: <s>[INST]▁message[/INST]▁reply</s>. Rendering the GGUF's Jinja template as text and tokenizing it would add a "▁" after [INST] and one before [/INST], 2 to 6 tokens per conversation the model did not see in training.

One cache, reused

Every layer keeps an f16 KV cache, 128 KiB per position over the 32 layers: 1 GiB at the default 8,192. A chat turn reuses the prefix it shares with the cache: the second turn of a two-turn test computes 8 of its 53 tokens (</s>, [INST], the message, [/INST]). mistral03_demo cache-test checks that extending, rewinding and single steps give bit-identical logits.

Tensors of one layer, plus the shared ones

Shapes are rows × cols, that is output × input, the way the kernels index them (the GGUF header lists them the other way round). Everything is Q8_0, embeddings and head included (the file has no rope_freqs tensor); the engine splits each 34-byte block into a q array (32 int8) and a d array (one f16), and stacks matrices that read the same input into one product.

Measured

RTX 4070 SUPER, both engines on the same Q8_0 file.

Speed

Decode reads 7.56 GB of weights per token (everything but the embeddings, which stay on the host): at 59.5 tokens/s that is 450 GB/s of the card's 504, level with llama.cpp. Prompt processing is 2.5× slower than llama.cpp's: the same gemm_q gap as in Llama 3.1 and the Qwen engines (no double buffering, 64 × 64 tiles).
