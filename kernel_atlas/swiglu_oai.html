gpt-oss · gptoss.ptx · element-wise, grid-stride

Inside swiglu_oai

Each gpt-oss expert computes two projections of the token, a gate g and an up value u, and combines them element by element before the down projection. OpenAI's variant clamps both inputs at ±7 and adds 1 to the up value. The kernel is the simplest kind there is: one thread per element, no cooperation, so this page is about two things, the arithmetic of one element and how a grid-stride loop spreads any n over a fixed-size grid.

out = xg · σ(1.702 · xg) · (xu + 1)   // xg = min(g, 7), xu = clamp(u, −7, 7)

Grid-stride: any n on a capped grid

      
The host launches 256-thread blocks, enough to cover n but at most 8 per SM: 448 blocks on this 56-SM card. Thread i handles elements i, i + stride, i + 2·stride … where stride = blocks × 256. During decode n is small and every thread does one element. During prefill n is far larger than the grid, so each thread loops.
