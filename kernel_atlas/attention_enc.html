Inside attention_enc

The encoder's attention: every token looks at the keys of its own text in both directions, within ±512 positions on local layers and over the whole text on global layers. Several texts share one batch, so the kernel first turns the token's text bounds and the window into one contiguous key range. With every key already computed (no cache, no decoding), it can afford an exact two-pass softmax: the scores of the range go to shared memory, then the maximum, the exponentials and their sum, then the weighted sum of the values.

outt,h = Σj∈[lo,hi) softmaxj(qt,h · kj) · vj   // [lo, hi) = t's text ∩ [t − 512, t + 512] on local layers; scale 1, no 1/√d

Which keys a token sees

The square is the attention pattern of one batch: row = query token, column = key token. Three texts are packed back to back; each token carries seg[t] = [start, end) of its text, so the other texts are simply outside its range. On local layers the range is cut further to the band |j − t| ≤ 512. Drag the query to move along the batch.

One block: 8 warps, one query, n keys

Warp w scores keys lo + w, lo + w + 8, … : each column of the grid is one round of 8 keys, each row one warp. Inside a warp the 32 lanes split the D dimensions (lane l takes l, l + 32, …) and a butterfly adds them up. Click a key to inspect it, or an output dimension to follow its thread.

Why it is built this way

    

      

        
Two passes instead of an online softmax

        
Gemma 3's decoder attention streams keys out of a cache and keeps a running maximum, rescaling its accumulator whenever the maximum grows. An encoder has a different budget: the key range is at most 1025 keys on local layers and the text length on global ones, so its scores fit in shared memory (4 bytes each; 32 KB for the 8192-token limit). Storing them makes the softmax exact and simple: one maximum, one exponential per key, one sum, no rescaling, and each score is computed once.

        
The query moves to shared memory once (up to 512 floats) because every warp reads all of it for every key. A key row is read with lane l taking dims l, l + 32, …, so each warp load is 128 contiguous bytes.

      

      

        
Packing texts without padding or masks

        
A batch is the texts laid end to end, no padding. Because a token's visible keys are always one interval, the "mask" is just two numbers: lo = max(start, t − 512) and hi = min(end, t + 513) on local layers, or the text bounds on global ones. No mask matrix is built and no masked key is ever scored; work per query is proportional to the keys it really sees.

        
The host sizes the dynamic shared memory for the longest range in the batch: min(1025, longest text) keys on local layers. Four query heads share the key and value rows of their kv head (2 on local layers, 1 on global), and neighbouring queries overlap almost all their keys, so most K and V reads hit in L2.
