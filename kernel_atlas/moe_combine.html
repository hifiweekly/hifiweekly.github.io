Inside moe_combine

After the down projection, each token has four expert outputs of 2880 values, one per expert the router chose. moe_combine mixes them with the router's weights and adds the result to the residual stream, in place. It is the last launch of every gpt-oss layer. One thread per output element; each reads the same element from the four expert rows.

x[t][i] = x[t][i] + Σj<4 w[t][j] · down[t][j][i]   // w from router_topk (sums to 1), down from mv_mxfp4 / gemm_mxfp4

Why it is built this way

    

      

        
Layout [token][expert slot][2880]

        
The down projection writes each (token, slot) pair's 2880 outputs as one contiguous row, so element i of slot j is at (t·4 + j)·2880 + i. A warp's 32 threads have 32 consecutive i, so each of its four loads from down is one 128-byte transaction, as are the loads of the residual and the store. The four weights are the same for the whole token and come from cache.

        
Splitting the flat index into (t, i) costs a div.u32, which is slow on GPUs (tens of instructions), but it runs once per element next to five memory reads.

      

      

        
Why the residual add is fused here

        
The attention half of the layer already folds its residual add into mv_q8 (the resid argument). The expert half cannot: four expert outputs have to be weighted and summed first, and only this kernel sees all four. So the sum and the add happen in one pass: x is read once and written once.

        
The weights of the four chosen experts sum to 1 (a softmax over the four), so the mix is an average of the experts' opinions, not a sum that grows with k.
